## 本轮主程序内置接入

用户要求可从设置切换这两套皮肤，因此本次不再仅修改设计目录：新增主程序内置选择、设置预览、任务视图卡片与随包本地素材。默认皮肤移除角色，明暗和强调色保留现有行为；换肤不改业务任务。

同时修复首次 WebUI 外观编辑的默认值来源：无本地记录时以已加载的后端外观作为起点，避免第一次换肤后刷新重置明暗、语言与强调色。空实例配置也通过统一导入恢复外观和全局设置，随后仍沿原流程创建初始实例。

任务表现优先取活动实例 `isRunning`，随后取整批 `Succeeded` / `Failed`，其余中性显示待机。不会把停止后的 `null` 当成成功、从 demo 搬入无事实来源的暂停/取消、或计算虚假百分比。角色互动只改组件本地表现；主程序的状态适配与离线模拟状态表分别说明在协议 §9.3 和 §10。

此接入由宿主 React 代码渲染固定资产，未开放第三方包、作者 HTML/脚本、原生命令或网络入口。第 7 节的安装、隔离与恢复门槛保持不变。

## 两处需要避免照搬的表述

- `App.tsx` 中有三处 Toolbar JSX 使用位置，但设置页、主视图和响应式分支并非同时可见的三份工具栏。应修的是可见实例注册和订阅生命周期，不能把源码出现次数当成运行时重复挂载证据。
- 当前 `extract_zip` 已有 `ensure_update_path` 目标路径检查；这比原 review 基线有所进展，但仍保留 `tar::Archive::unpack`，也没有满足皮肤专用的实际解压预算与所有条目约束。不能宣称“更新工具完全没有路径保护”，也不能据此复用成皮肤安装器。

## 验证边界

协议、离线 demo 与研究素材位于 `docs/design/skin-system/`，主程序内置组件、设置、外观持久化和素材位于 `src/`。设计目录的独立开发检查用 `npm ci`、`npm run generate`、`npm run check` 复现；主程序检查使用仓库根目录的测试和构建流程。浏览器布局、交互与截图检查只说明已测试的浏览器与视口；不会替代 Windows WebView2、macOS WKWebView、Linux WebKitGTK 的权限负向测试。

离线 demo 已通过 37 组文档/DOM/事件检查，`npm run check:browser` 在 Chromium 155 中 18 项通过，包括新两套的五种视口布局、原六套在 850×525 下的任务操作、实际 H.264 解码播放和系统减少动效。两份原动作视频的请求、速度、清理与跨角色隔离有独立回归。680×420、566×350 是 850×525 在 125%/150% 缩放下的有效 CSS 空间模拟，不是原生窗口实测。受管理浏览器策略禁止直接 `file://` 导航，该项标为跳过；全部运行素材经本地 HTTP 加载验证。这些数字不作为本轮主程序内置接入的测试结果。

本轮 `pnpm build` 通过；根测试为 127 项通过、1 项既有平台跳过、0 失败；`npm run check:integration` 的真实 App/设置 Chromium 检查 11 项通过，新增社区原片吃饭动作静音播放与减少动效验证，并确认角色没有对白段落。后端为受控测试替身，未操作设备。原生 WebView 与通用隔离验收仍未完成。

上述通用生产安全与接入项继续作为第三方导入的阻断条件。新增可信内置皮肤不扩大来源信任，不增加原生、文件或网络权限。
